Help & User Guide

This app is an offline, single-file business management tool for small shops and traders. Everything you enter is stored locally (IndexedDB) on your device — no data leaves your device unless you export it.

Quick overview

  • Products — add any product with a free-text name and category, image, retail price and cost. Product names are used to identify items; the app prevents exact-name duplicates by default and offers a merge tool.
  • Stock — add incoming stock (optionally mark as New stock and supply unit price and unit cost). You can add multiple stock "layers" in a single operation. Stock entries carry price/cost and a timestamp.
  • Sales — record sales by selecting product, quantity and (optionally) unit price and paid amount. The app consumes stock using FIFO from the oldest positive stock batches and calculates profit using the consumed batch costs.
  • Expenses — simple expense tracker for overheads and bills.
  • Reports & Export — simple charts and an Excel (.xlsx) export (SheetJS). If SheetJS is unavailable the app will fall back to a JSON export.
  • Search — per-page search boxes (Products, Stock, Sales, Expenses) plus a global search in the header that looks across everything and shows grouped results in a modal.

How the important flows work

Adding a product
  1. Open Products → enter Name (free text), Category (free text), optional image, Price and Cost → click Add Product.
  2. If a product with the exact same name already exists, the app will prompt you and give you the option to open Stock to add inventory to the existing product. To create a truly separate product, use a unique name.
  3. If you later discover duplicates, use Merge duplicate names (Settings or Products) — this merges inventories, re-points sales and stock records to the kept product, and removes duplicates.
Adding stock
  1. Open Stock → choose product and quantity.
  2. Check New stock? to attach a unit price and a unit cost to that stock addition. You can also add up to 3 extra layers in the same operation (main + up to 3 extras).
  3. Each layer becomes a stock entry stored with its own timestamp, price and cost (if provided). Inventory totals are updated automatically.
Making a sale
  1. Open Sales → choose product, quantity, optional Unit price and optional Paid amount → click Add Sale.
  2. Unit price is the expected retail price. If you leave it empty the product's stored price is used.
  3. Paid is the actual amount the customer gave. If provided and > 0 the app uses the paid amount as the actual sale total (so you can record sales made below/above the expected price).
  4. Stock is reduced using FIFO by consuming the oldest positive stock batches first. The sale stores a cost basis (sum of unit costs consumed) so profit = actual total − cost basis.
  5. The Sales table shows both expected vs actual information: Unit column displays expected unit price and, when different, the paid-per-unit in parentheses (e.g. KES 1000 (paid KES 900)). The Profit column shows the actual profit and the expected profit (muted) if they differ.

Stock listing & details

  • The Stock page shows an aggregated, neat view: one row per product with the format availableQty (-soldQty) (for example 97 (-3)). This keeps the main table uncluttered.
  • Click Details on a product row to open a modal with the full history of stock entries (incoming batches, sold entries, timestamps, price and cost for each batch).
  • This preserves the full audit trail but avoids listing each sale as a negative line in the main stock table.

Search

  • Each section has a search box (Products, Stock, Sales, Expenses) — typing filters the visible list instantly.
  • The header global search scans products, sales, stock and expenses and shows grouped results in a modal (quick way to find an item across the whole app).

Export & Import

  • Use Export (Excel) to download an .xlsx file containing Products, Sales, Stock and Expenses. The export includes stock price/cost and sales cost basis.
  • If the Excel library (SheetJS) can't be loaded the app will automatically download JSON instead.
  • Import accepts JSON exported by this app — import will replace current local data (you are asked to confirm before the overwrite). After import the app recalculates product inventories from stock entries.

Duplicate handling

  • By default the app prevents adding an exact-name duplicate product. If you choose to create separate items, use unique names.
  • If duplicates already exist use the Merge Duplicate Names tool — it combines inventory and updates existing sales & stock to reference the single keeper product.

Performance tips

  • The app uses a client-side cache and debounced rendering to avoid re-reading the database on every interaction. That keeps it fast even on modest devices.
  • If you have very large datasets (thousands of rows) consider: exporting and archiving older data, or enabling pagination/virtualized lists (we can add this if needed).

Troubleshooting & FAQs

  • Buttons not responding? Make sure you are running the page in a standard browser tab. Electron/Nativefier wrappers sometimes alter behavior — the app attempts to detect Electron and disable service workers, but UI should still be functional. Try a modern Chromium or Firefox browser if you see oddities.
  • Export didn't download .xlsx? The app loads SheetJS from a CDN; if offline it will provide a JSON fallback. Reconnect to the internet to get .xlsx export working, or host the app with the SheetJS script locally.
  • Inventory not matching? Run a manual check: open Settings → Merge duplicates (if you have same-name products) then use Reset Stock or re-import after you verify the stock history. The app always recomputes product inventory from stock entries on import/reset.
  • Need audit details? Use the Stock → Details modal to see per-batch price, cost and timestamp. Sales records include stored unitPrice, actual paid (if supplied), and the computed costBasis used to calculate profit.
