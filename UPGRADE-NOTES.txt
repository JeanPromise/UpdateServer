KENYA BARCODE HUB — ADMIN / IMAGE API UPGRADE

IMPORTANT WHEN UPDATING RENDER
- Update the existing deployed service/repository if you want to keep its current customers, payments, API keys and barcode records.
- Keep its existing persistent disk mounted at /var/data. On startup, the app migrates the existing database in place and preserves recognised older database layouts.
- Keep the ADMIN_USERNAME and ADMIN_PASSWORD environment variables configured in Render. They are still used for the admin sign-in.
- Do not commit a live SQLite database or customer backup to GitHub. The unrelated root-level db.sqlite3 and users.db files from the supplied project archive were intentionally not included in this deploy bundle.

ADMIN ADDITIONS
- Dashboard barcode and image-coverage totals.
- Product image library: browse linked images, locate missing images, paste trusted image URLs, upload product photos, export image links and back up locally uploaded image files.
- Public image discovery checks up to five missing barcodes per click and enforces a short cooldown. It will not invent an image when no match is found.
- Image-inclusive API plans are separate from standard plans. They are hidden/unpriced by default; set the actual KSh prices and publish them in Admin > Plans & pricing before selling them.
- Customer support: inspect plans, payments, API outcomes and login events; correct profile details; issue a temporary password; issue/revoke API keys.
- API health and diagnostics, including HTTP 401, 402, 404, 429 and 5xx outcomes.

CATALOGUE
- The data-seed folder contains barcode-hub-catalogue-1567-2026-10-22.csv, exported from the supplied backup. It contains 1,567 distinct barcode records and an initially blank image_url column.
- On a fresh/empty site, import that CSV from Admin > Product catalogue to load those records. On the existing persistent database, don't import unless you intend to upsert the catalogue.
- Existing records are migrated with blank image fields; the uploaded backup did not contain product-image links or image files.

IMAGE COVERAGE AND BACKUPS
- Image discovery is incremental and relies on matches in a public product catalogue; this cannot guarantee a picture for every barcode, especially local products.
- Manually attach a verified image URL, upload an image, or import a CSV with barcode/name/image_url for products that aren't found.
- Database backups keep image links and metadata. Locally uploaded image binaries are stored in product-images/ and must be downloaded separately using Admin > Product images > Download image files ZIP. Keep both backups.
- Review each image source's reuse/licensing terms before reselling externally sourced image data.

VALIDATION
- Python syntax compilation and Jinja template parsing pass.
- SQLite schema migration checks pass for both older backup layouts (with or without visitor_events.user_id), with product records and existing visitor-user links preserved.
- The build environment used to prepare this ZIP did not have Flask installed and had no package-network access, so a live HTTP integration test could not be run here. Render installs Flask/Gunicorn from requirements.txt during deployment.
